# Contento

**Live:** https://contento-1df87.web.app

Single Flutter codebase targeting web, iOS, Android, and Windows desktop, with adaptive chrome per platform (Cupertino on iOS, Material on Android, a sidebar layout on web/desktop).

## Stack

| Layer | Tech |
|---|---|
| App | Flutter + Riverpod |
| Auth | Firebase Authentication (email/password) |
| Database | Cloud Firestore |
| Image storage | Cloudinary (unsigned client uploads) |
| Hosting | Firebase Hosting |

## Core idea

- **Employee** — sees only an anonymized `Project #N — [generic title]` with posts under it. Writes captions, attaches images, submits for review. Can also originate new posts themselves (title, due date, brief, and all).
- **Admin** — sees everything: creates projects, assigns them to one employee each, provisions employee/admin accounts, reviews the submissions queue (approve / reject with feedback / edit inline), and marks approved posts as scheduled.

No self-serve signup — accounts are always provisioned by an admin through the app (Employees → Add Employee).

## Project structure

```
lib/
  app.dart                 — MaterialApp/CupertinoApp switch, theming, session routing
  main.dart                — Firebase init entrypoint
  firebase_options.dart    — generated by `flutterfire configure`, do not hand-edit
  theme/                   — brand colors, typography, platform-detection helpers
  models/                  — Employee, Project, Post (+ Firestore (de)serialization)
  state/
    app_state.dart         — Riverpod providers, all backed by live Firestore streams
    image_upload.dart      — Cloudinary upload client
  auth/                    — login screen
  employee/                — My Project, Post detail, New Post, My Submissions, My Calendar
  admin/                   — Overview, Submissions Queue, Projects, New/Add Post,
                              Content Calendar, Employees, Add Employee, Settings
  widgets/                 — shared StatusBadge, PostCard, calendar grid, adaptive shell
firestore.rules            — security rules (admin-only writes to employees/projects,
                              employees scoped to their own project's posts)
firebase.json / .firebaserc — Hosting + Firestore deploy config
```

## Getting started

### Prerequisites

- Flutter SDK (3.13+)
- A Firebase project with **Authentication** (Email/Password provider) and **Firestore** enabled
- A free [Cloudinary](https://cloudinary.com) account

### 1. Clone and install

```bash
git clone https://github.com/thisisjanith/contento.git
cd contento
flutter pub get
```

### 2. Connect your own Firebase project

```bash
npm install -g firebase-tools
dart pub global activate flutterfire_cli
firebase login
flutterfire configure
```

This generates `lib/firebase_options.dart` for your project.

### 3. Configure Cloudinary

In `lib/state/image_upload.dart`, set:

```dart
static const cloudName = 'your-cloud-name';       // from your Cloudinary dashboard
static const uploadPreset = 'your-preset-name';    // Settings → Upload → Upload presets
```

The upload preset must be **Unsigned** — that's what lets the Flutter client upload images directly with no backend.

### 4. Bootstrap the first admin account

There's a chicken-and-egg problem: admins provision every other account, but the first admin has to be created by hand.

1. Firebase Console → **Authentication → Add user** → your email + a password
2. Firebase Console → **Firestore Database → Start collection**
   - Collection ID: `employees`
   - Document ID: the UID shown next to the user you just created
   - Fields: `name` (string), `email` (string, matching), `role` (string, value `admin`)

Every account after that can be created from **Employees → Add Employee** inside the app.

### 5. Deploy security rules

```bash
firebase deploy --only firestore:rules
```

### 6. Run it

```bash
flutter run -d chrome     # web
flutter run -d windows    # desktop
flutter run                # whichever device/emulator is attached
```

## Deploying

```bash
flutter build web --no-tree-shake-icons
firebase deploy --only hosting
```

## Design system

- **Primary:** Indigo `#5B4FE5` · **Accent:** Orange `#F2703C` (Needs Revision / attention states only)
- **Approved:** Green `#1F8A4C` · **Background:** warm off-white `#F8F6F1`
- **Type:** Space Grotesk (headings) + IBM Plex Sans (body/UI), bundled as local font assets — not Roboto/Inter/system default
- Status colors (Pending / Submitted / Needs Revision / Approved) are centralized in `theme/colors.dart` and consumed everywhere via the shared `StatusBadge` widget — never reimplemented per screen
